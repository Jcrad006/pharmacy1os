# Python parity increment 53 — check synthetic claim response integrity

Follows [Increment 52](PYTHON_PARITY_PROGRESS_INCREMENT_52.md) on `python-native-rewrite`. Narrows **billing audit-trail and correction safety** gaps without adding external adjudication.

## Implemented
- Added **response SHA-256** next to existing request SHA-256 to every append-only local `SandboxClaimTransaction` record (BILL, REVERSE, TEST_REJECT, TEST_RESOLVE, TEST_RETRY). Creation asserts the outcome recorded in the response agrees with the event status. All record-reading `_view` paths now independently verify canonical request hash, canonical response hash, JSON object shapes, and recorded response outcome.
- Native Third Party workspace validates the latest activity, linked reversal/resolution/retry events, and the separately paged *open* rejection queue. The pharmacist test-rejection queue and resolution path also validate the original response evidence. A modified mock insurer rejection or payment fails closed, rather than silently appearing as a valid claim.
- Pharmacist verification, claim review, versioned COB history, selective correction, and full-chain reversion already use the validated event view, so they now refuse a changed synthetic response before consuming inventory or changing payer attempts. Site and permission checks remain unchanged.
- Alembic revision `d52f1ab36c90` backfills response digests from actual prior local mock events, **after validating original request hashes and response outcome**. Corrupt legacy history aborts the migration instead of being blessed by a new digest; SQLite and PostgreSQL migrations preserve the isolated `py_*` schema. For older local synthetic SQLite desktop databases, `create_schema` adds and validates this column exactly once, without automatically rewriting any previously present digest.
- Added regression tests for matching paid/reversed hashes, tampered paid/rejection/reprocessed responses, outcome-digest mismatch, atomic refusal to record contradictory local adapters, API rejection, site boundaries, and no inventory mutation. Pre-existing migration backfill fixture now inserts historical rows using its true old table schema.

## Limits and next priority
A SHA-256 stored in the same database as its payload offers **accidental modification detection and internal consistency checks**, not a tamper-proof cryptographic attestation against an adversary who can rewrite both the payload and digest. Before production, append-only/WORM protection, keys or external log anchoring, application-level access control and real payer provenance would still be needed. The next parity focus should be **rejected payer-claim lifecycle and patient-level COB correction history**, using the existing synthetic-only versioned attempts. The frozen audit is not a full-parity claim. No real insurer contact, actual dispensing or production patient data is supported. PR #43 remains draft.
