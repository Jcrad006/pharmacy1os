# Python parity increment 32 — bottle-specific manufacturer LOT/EXP in print evidence

**Branch:** `python-native-rewrite`. Follows [increment 31](PYTHON_PARITY_PROGRESS_INCREMENT_31.md). Strengthens label parity item **FL14** without changing the synthetic label issuance policy.

For each physical bottle generated by `prepare_for_review`, `enqueue_label_jobs` now loads the exact `FillSource` matching that bottle's quantity-descending source order; validates NDC, description, bottle count, source quantity and site ownership; and freezes the source ID, stock ID, manufacturer lot, manufacturer expiration and declared original-container packaging into the already SHA-256 protected label-job JSON snapshot.

A preview now shows **SCANNED LOT**, **MANUFACTURER EXP**, original-container versus prescription-container packaging, and an explicitly pending/not-verified patient discard-date status for repackaged stock. This avoids implying that a pharmacist has verified a patient discard date before `PharmacyService.verify` computes it. Earlier print-job records can still be viewed with clear **legacy snapshot not recorded** markers rather than fabricated lot values.

This is **not a production labeling engine** or assurance of NC compliance: the reference snapshot is produced before pharmacist verification, no calculated patient discard date is printed after verification, no printer/device acknowledgement exists, and no real dispensing label is authorized. The UI remains watermarked **SYNTHETIC TEST LABEL - NOT FOR PATIENT USE**.

Regression tests assert that two different manufacturers have their **own** scanned lot/expiration in two distinct immutable print records, and that original-container packaging state is frozen at label queue time. No new migrations are required.
